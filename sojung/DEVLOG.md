# DEVLOG

## 2026-08-26 — 프로젝트 시작, 기본 뼈대 세팅

### 배경 / 목표
재고관리와 거래처 관리(입출금, 미납금, 선납금)를 함께 처리하는 사내 전용 서비스를 만들기로 함.
요구사항:
- 회사 사람들만 사용 (외부 공유 없음)
- 회사 내부 컴퓨터들끼리만 데이터 공유
- 기능은 사용자가 하나씩 지정해가며 순차적으로 추가

### 배포/공유 구조 결정
"사내 컴퓨터들끼리만 공유"라는 요구를 만족시키기 위해, 클라우드 배포 대신
**사내 서버(PC) 한 대에 앱을 띄우고, 다른 PC들은 같은 LAN에서 브라우저로 접속**하는 구조로 결정.
- 서버 PC: Next.js 앱 실행 + SQLite 파일 보관
- 다른 PC: 서버 PC 주소로 접속해서 화면만 사용, 데이터를 직접 다루지 않음
- 서버 PC가 꺼지면 접속 불가 → 상시 가동 PC를 서버로 지정 필요

### 기술 스택 결정
- **Next.js + JavaScript** — 프론트엔드/백엔드 통합 프레임워크. TypeScript도 제안했으나,
  더 대중적이고 진입장벽이 낮다는 이유로 JavaScript로 결정.
- **Tailwind CSS** — 표 위주 UI(재고표, 거래처 목록 등)를 빠르게 만들기 위해 채택.
- **SQLite (better-sqlite3)** — 별도 DB 서버 설치·운영 없이 파일 하나로 DB 관리 가능.
  사내 PC 한 대 배포 구조와 궁합이 좋고, 백업도 파일 복사로 끝남.
  트래픽이 크지 않은 사내 업무용 서비스라 동시 쓰기 제약은 문제 되지 않을 것으로 판단.

### 서비스 간 연결 구조 (현재까지)
아직 기능(재고, 거래처, 입출금 등)은 추가되지 않은 초기 단계.
현재는 다음 한 가지 연결만 존재:
```
Next.js API Route (/api/health)
        ↓ import
src/lib/db.js (better-sqlite3 싱글턴 커넥션)
        ↓
data/sojung.db
```
앞으로 추가될 기능(재고관리, 거래처관리 등)도 모두 이 `src/lib/db.js`를 통해
같은 SQLite 파일에 연결해서, 하나의 DB 안에서 재고 데이터와 거래처 데이터가
서로 참조(예: 거래처별 재고 이동 내역)할 수 있는 구조로 이어갈 예정.
