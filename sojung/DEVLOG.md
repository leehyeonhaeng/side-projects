# DEVLOG

## 2026-08-26 — 프로젝트 시작, 기본 뼈대 세팅

### 배경 / 목표
재고관리와 거래처 관리(입출금, 미납금, 선납금)를 함께 처리하는 사내 전용 서비스를 만들기로 함.
요구사항:
- 회사 사람들만 사용 (외부 공유 없음)
- 회사 내부 컴퓨터들끼리만 데이터 공유
- 기능은 사용자가 하나씩 지정해가며 순차적으로 추가

### 배포/공유 구조 결정
"사내 컴퓨터들끼리만 공유"라는 요구를 만족시키기 위해, 클라우드 배포 대신
**사내 서버(PC) 한 대에 앱을 띄우고, 다른 PC들은 같은 LAN에서 브라우저로 접속**하는 구조로 결정.
- 서버 PC: Next.js 앱 실행 + SQLite 파일 보관
- 다른 PC: 서버 PC 주소로 접속해서 화면만 사용, 데이터를 직접 다루지 않음
- 서버 PC가 꺼지면 접속 불가 → 상시 가동 PC를 서버로 지정 필요

### 기술 스택 결정
- **Next.js + JavaScript** — 프론트엔드/백엔드 통합 프레임워크. TypeScript도 제안했으나,
  더 대중적이고 진입장벽이 낮다는 이유로 JavaScript로 결정.
- **Tailwind CSS** — 표 위주 UI(재고표, 거래처 목록 등)를 빠르게 만들기 위해 채택.
- **SQLite (better-sqlite3)** — 별도 DB 서버 설치·운영 없이 파일 하나로 DB 관리 가능.
  사내 PC 한 대 배포 구조와 궁합이 좋고, 백업도 파일 복사로 끝남.
  트래픽이 크지 않은 사내 업무용 서비스라 동시 쓰기 제약은 문제 되지 않을 것으로 판단.

### 서비스 간 연결 구조 (현재까지)
아직 기능(재고, 거래처, 입출금 등)은 추가되지 않은 초기 단계.
현재는 다음 한 가지 연결만 존재:
```
Next.js API Route (/api/health)
        ↓ import
src/lib/db.js (better-sqlite3 싱글턴 커넥션)
        ↓
data/sojung.db
```
앞으로 추가될 기능(재고관리, 거래처관리 등)도 모두 이 `src/lib/db.js`를 통해
같은 SQLite 파일에 연결해서, 하나의 DB 안에서 재고 데이터와 거래처 데이터가
서로 참조(예: 거래처별 재고 이동 내역)할 수 있는 구조로 이어갈 예정.

## 2026-08-27 — 전체 기능 정리 및 1단계 재고관리 구현

### 전체 기능 범위 및 구현 순서 정리
재고관리, 거래처관리, 입출금/잔액/알림, 미납금/선납금, 공통(로그인·엑셀 내보내기·영수증·대시보드) 5개 영역으로
전체 기능을 정리하고 사용자와 우선순위를 합의함. 원래 "입출금 관리"와 "미납금/선납금 관리"를 별도 기능으로
나눴으나, 거래처별 잔액 데이터를 공유한다는 점에서 하나의 도메인(입출금·잔액·알림)으로 재구성.
구현 순서: 재고관리 → 거래처관리 → 입출금·잔액·알림 → 미납/선납금 → 공통/기반.

전체 목록과 각 기능의 결정 배경을 정리한 문서를 아티팩트로 만들어 공유함 (조직 외부 공유가 막혀 있어
바탕화면에 `Sojung 기능 명세서.html` 파일로도 저장).

### 1단계: 재고관리 구현
품목 등록/수정/삭제, 입고·출고·재고조정 등록, 품목별 입출고 이력, 최소재고 미달 시 시각적 강조,
품목 검색을 구현.

- `src/lib/db.js` — DB 연결부에 스키마 초기화 추가 (`items`, `stock_movements` 테이블, `CREATE TABLE IF NOT EXISTS`)
- `src/lib/inventory.js` — DB 접근 계층(DAL): 품목 CRUD, 입출고 이력 조회/등록. 현재 재고는 별도 컬럼으로
  중복 저장하지 않고 `stock_movements`를 집계해 항상 파생 계산 (in +, out -, adjust는 부호 있는 증감분)
- `src/app/items/actions.js` — Server Actions (`'use server'`): 품목 생성/수정/삭제, 입출고 등록.
  검증 실패나 삭제 제한(이력이 있는 품목) 시 `?error=`로 리다이렉트해 안내
- `src/app/items/page.js`, `new/page.js`, `[id]/page.js`, `[id]/edit/page.js`, `ItemForm.js` — 목록/등록/상세/수정 화면
- `src/app/page.js` — 기본 템플릿 대신 `/items`로 리다이렉트

결정 사항 (사용자 확인):
- 단가는 품목에 고정하지 않고 거래(입출고)마다 입력
- 수량은 소수점 허용 (kg, L 단위 등)
- 거래처 연동은 2단계(거래처관리) 이후 추가 예정, 이번 단계는 품목 단위로만 관리
- 재고 부족 시에도 출고 자체는 막지 않고 목록/상세에서 시각적으로만 경고

Next.js 16.3.3부터 `middleware.js`가 `proxy.js`로 대체된 점을 확인 (이번 단계는 로그인이 없어 직접 영향 없음,
다음 로그인 구현 시 참고). 데이터 변경은 Server Actions(`'use server'` + `<form action>`) 패턴을 사용.

브라우저(Chrome)로 품목 등록 → 입고/출고/조정(소수점 포함) → 재고 자동 갱신 → 최소재고 미달 강조 →
이력 있는 품목 삭제 차단 → 검색까지 전체 흐름 직접 확인. `npm run build` 통과 확인.
