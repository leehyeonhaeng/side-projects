# 행컴퍼니 설계 (회사 업무 공간)

> 인쇄·사무기기 임대 업체용 소규모 ERP. 행포털 안의 별도 공간으로 들어가 거래처·기기·재고·임대 계약·돈·증빙 문서를 **하나의 흐름**으로 관리한다.
> 행포털 공통 설계(로그인, 권한 미들웨어, 단일 테이블, 배포)는 `DESIGN.md`를 따르고, 이 문서는 회사 공간만 다룬다.
> 상태: 설계 확정(2026-10-06), **C1·C2 (2026-10-06), C3~C6 (2026-10-07) 구현·dev 배포**

---

## 1. 배경과 목표

- 같은 업체용으로 만든 `sojung`(LAN 전용, Next.js + SQLite)은 기능마다 따로 기록해서 서로 연동되지 않았다. 예: 입출고에 거래처가 없고, 돈(payments)이 재고·기기와 연결되지 않음
- 행컴퍼니는 **"거래 하나를 입력하면 재고·기기·거래처 잔액·회사 장부·증빙 문서가 함께 바뀌는"** 구조로 처음부터 다시 만든다
- 현장 직원이 **폰으로** 쓰는 것을 기본으로 한다 (지금은 수기 작성 후 사무실 전달, 전화 주문)
- sojung 데이터는 데모라 옮기지 않는다. 대신 고객 시연용 **데모 데이터**를 풍부하게 넣는다

## 2. 확정된 결정 (사용자, 2026-10-06)

| 항목 | 결정 |
|---|---|
| 위치 | 행포털 안의 별도 공간. 행포털 홈에서 회사로 들어가면 회사 전용 홈·메뉴 |
| 대상 | 지금은 회사 1곳. 잘 되면 다른 회사에 공급 — **회사마다 AWS 계정을 따로** 두고 같은 코드로 배포. 데이터 구조는 회사 여러 개를 받을 수 있게 열어 둠 |
| 회사별 차이 | 코드 수정 대신 **설정**(기능 켜기/끄기, 회사 정보, 직인, 문서 양식·번호 규칙)으로 |
| 직원 | 회사당 20명 이하. 현장 직원은 폰 사용 |
| 직원 가입 | **회사 관리자가 초대**(초대 링크·코드를 카톡 등으로 전달) → 그 링크로 가입하면 바로 그 회사 직원 + 정해 둔 역할. Host 승인 불필요 |
| 직원 화면 | 로그인하면 **행포털 홈**. 회사도 쓰고, 권한이 있으면 개인 기능(일정·할 일·메모 등)도 쓴다 |
| 권한 | 직원마다 영역별 권한 + **금액 보기 끄기**(대여 업무는 하되 금액은 서버에서부터 숨김) |
| 임대료 | 기기 모델에 정가, **실제 금액은 거래처 계약마다** 따로(정가가 기본값). 계약마다 **월 고정** 또는 **기본료 + 초과 매수(카운터 검침, 흑백·컬러 따로)** |
| 부가세 | 금액 줄마다 **포함 / 별도 / 면세** 선택. 공급가액·세액은 자동 계산해 채우되 **사람이 직접 고칠 수 있고** 합계는 고친 값 기준 |
| 돈 입력 | 금액은 사람이 직접 입력(자동 계산은 제안값). 입력한 금액을 기준으로 잔액·장부·문서가 따라 바뀜 |
| 증빙 문서 | 회사 직인이 찍힌 **PDF**(영수증·거래명세서·청구서·거래처 원장·기기 라벨). 다운로드·폰 공유·출력만 (이메일 자동 발송 없음). 직인은 예시 이미지로 시작, 설정에서 교체 |
| 보증금 | 지금은 넣지 않음. 고객이 필요하다고 하면 추가 |

## 3. 핵심 원칙

1. **거래 중심**: 직원이 입력하는 것은 "거래"(판매, 매입, 임대 출고, 수거, 입금, 지급, 청구, 경비) 하나. 나머지는 그 거래가 만든다
2. **한 번에 같이 바뀐다**: 거래 하나가 바꾸는 모든 항목(재고 수량, 기기 상태, 거래처 잔액, 계좌 잔액, 문서)은 DynamoDB 트랜잭션 한 번으로 저장. 하나라도 실패하면 아무것도 안 바뀐다 (예: 이미 임대 중인 기기를 또 출고하면 거절)
3. **지우지 않고 취소한다**: 확정된 거래·발행된 문서는 삭제하지 않고 "취소" 거래로 되돌린 뒤 다시 입력. 증빙과 장부가 항상 맞는다
4. **모든 변경을 남긴다**: 누가 언제 무엇을 했는지 회사 활동 기록
5. **월 마감**: 마감한 달의 거래는 수정·취소 불가 (관리자가 마감 해제 가능, 기록 남김)

## 4. 화면 구성

**진입**: 행포털 홈의 "행컴퍼니" 아이콘·위젯 → `/company` (회사가 여러 개면 회사 고르기). 회사 안에서는 회사 전용 사이드바(PC) / 하단 탭(폰)

| 메뉴 | 내용 |
|---|---|
| 홈 (대시보드) | 오늘 할 일(출고 예정·검침 예정·점검), 미수금 상위, 이번 달 매출·입금, 재고 부족, 계약 만료 임박, 빠른 입력 버튼 |
| 거래처 | 매출처·매입처·둘 다. 상세: 잔액(미수·선수·미지급), 보유 기기, 계약, 거래 내역, 문서, 원장 출력 |
| 기기 | 임대 장비 한 대씩(고유번호 `HC-000123`). 상태(창고·임대 중·수리·폐기), 현재 위치, 이력(출고·수거·A/S·검침), 라벨 출력. **라벨 QR을 폰 카메라로 찍으면 이 화면이 열림** |
| 품목·재고 | 품목 = "개체 관리"(복합기·프린터 모델) 또는 "수량 관리"(토너·잉크·용지·부품). 재고 수량, 최소 재고, 정가·기본 임대료 |
| 임대 계약 | 거래처 + 기기들 + 요금(월 고정 / 기본료+초과 매수) + 청구일 + 기간. 매달 자동 청구 |
| 거래 | 거래 입력(종류 선택 → 단계별 입력) 및 목록. 폰에서는 "출고", "수거", "검침", "입금", "판매" 빠른 버튼 |
| 돈 | 미수금·미지급금 목록, 입금·지급 처리, 계좌(현금·통장)별 잔액, 회사 장부(입출금 내역) |
| 문서함 | 발행한 모든 문서(번호순), 다시 받기·공유·출력, 취소 표시 |
| 보고서 | 월별 매출·매입·수금, 거래처별, 품목별, 기기 가동률. 엑셀(CSV) 내보내기 |
| 설정 | 회사 정보(상호·사업자번호·대표·주소·연락처·입금 계좌), 직인, 문서 번호 규칙, 기본 부가세, 기능 켜기/끄기, 월 마감 |
| 직원·권한 | 초대 링크 만들기, 직원 역할·권한, 내보내기 (회사 관리자만) |

## 5. 거래 종류와 자동 처리

| 거래 | 입력 | 자동으로 바뀌는 것 | 문서 |
|---|---|---|---|
| **임대 출고** | 거래처, 기기(QR 스캔 가능), 계약(새로 또는 기존), 첫 청구 여부 | 기기: 창고 → 임대 중 @거래처 / 계약에 기기 추가 / (첫 청구 시) 청구 거래 생성 → 미수 증가 | 기기 라벨, 출고 확인서 |
| **수거** | 기기, 수거 시 카운터 | 기기: 임대 중 → 창고 / 계약에서 빠짐(마지막 기기면 계약 종료) / 카운터 기록 → 미청구분 정산 청구 | 수거 확인서 |
| **판매** | 거래처, 품목·수량·단가·부가세 | 재고 감소 / 거래처 미수 증가 (즉시 결제면 입금까지 함께) | 거래명세서 (+ 영수증) |
| **매입** | 매입처, 품목·수량·단가 (개체 품목이면 기기 자동 등록·고유번호 부여) | 재고 증가·기기 생성 / 미지급 증가 | 입고 내역 |
| **청구** (정기·수동) | 계약 → 자동 / 수동은 거래처·항목 | 거래처 미수 증가 | 청구서 |
| **검침** | 기기, 흑백·컬러 카운터 | 지난 검침 대비 사용량 → 기본 매수 초과분 계산 → 다음 청구에 반영 | — |
| **입금** | 거래처, 금액, 계좌, 날짜 | 오래된 청구부터 자동 배분(직원이 조정 가능) → 미수 감소, 남으면 선수금 / 계좌 잔액 증가 | **직인 영수증** |
| **지급** | 매입처, 금액, 계좌 | 미지급 감소 / 계좌 잔액 감소 | 지급 증빙 |
| **경비** | 항목(임차료·인건비·유류비 등), 금액, 계좌 | 계좌 잔액 감소 / 장부 | — |
| **A/S·점검** | 기기, 내용, 사용 부품 | 기기 이력 / 사용 부품 재고 감소 / (유상이면) 청구 | 작업 확인서 |
| **취소** | 원래 거래 | 원래 거래가 바꾼 것을 모두 되돌림, 문서에 "취소" 표시 | — |

**잔액 정의 (거래처 하나)**: `미수 = 청구 합 − 입금 배분 합`, `선수 = 배분되지 않은 입금`, `미지급 = 매입 합 − 지급 합`. 거래가 저장될 때 거래처 항목의 잔액 값도 같이 갱신(목록·대시보드가 빠르게)

## 6. 금액 입력 규칙

- 금액 줄: 수량 × 단가 → 부가세 모드에 따라 공급가액·세액 **제안값** 계산(원 단위, 세액 = 공급가액의 10% 반올림)
  - 포함: 합계 = 입력 금액, 공급가액 = 합계 ÷ 1.1
  - 별도: 공급가액 = 입력 금액, 세액 = 10%
  - 면세: 세액 0
- 공급가액·세액·합계는 칸마다 직접 고칠 수 있음. 고친 칸은 표시되고, 거래 합계는 줄 합계의 합
- 금액은 원 단위 정수
- "금액 보기"가 꺼진 직원: API가 단가·금액·잔액 필드를 아예 보내지 않음. 금액 없이 할 수 있는 거래(출고·수거·검침·A/S)만 입력 가능

## 8. 권한

**두 단계**
1. 행포털 단계 (기존): 개인 모듈(일정·할 일·식단 등) 권한. 회사 직원은 Host가 정한 "회사 직원 기본" 프리셋으로 시작
2. 회사 단계 (신규): 회사 멤버십 + 역할 + 영역별 권한

| 영역 | 내용 |
|---|---|
| 거래처, 기기, 품목·재고, 계약, 거래, 돈, 문서, 보고서, 설정 | 영역마다 없음 / 보기 / 편집 |
| 금액 보기 | 켜기/끄기 (끄면 모든 화면·API에서 금액 숨김) |
| 직원 관리 | 회사 관리자만 |

**역할 프리셋** (회사 관리자가 수정 가능): 관리자(전부), 경리(돈·문서·보고서·거래처, 기기 보기), 사무(거래처·계약·거래·문서, 금액 보기), 현장 기사(기기·출고·수거·검침·A/S, 금액 숨김)

**초대 가입 흐름**
```
1. 회사 관리자: 직원·권한 → 초대 만들기(역할 선택) → 초대 링크(7일 유효)
2. 직원: 링크 열기 → 가입(이름·이메일·비밀번호) → 이메일 인증
3. 가입 확정 트리거: 초대 코드 확인 → (Host 승인 없이) 계정 활성 + 회사 멤버 + 역할 + 행포털 "회사 직원 기본" 권한
4. 로그인 → 행포털 홈 → 행컴퍼니
```

## 9. 기술 구조

| 항목 | 결정 |
|---|---|
| 백엔드 | 새 Lambda `company` (회사 데이터·문서 S3만 접근하는 최소 권한), 경로 `/api/v1/company/{proxy+}` |
| 데이터 | 같은 단일 테이블, 회사 파티션 `COMPANY#<회사id>`. 거래 저장은 `TransactWriteItems`(조건 검사 포함) |
| 문서 저장 | S3 버킷 `portal-<env>-docs-lhhportal`(비공개, 버전 관리, 암호화). 받기는 API가 base64(내려받기·공유) + 10분 서명 URL(새 탭 열기·인쇄)을 같이 준다 |
| PDF 생성 | Python(reportlab 5) + Pretendard(`backend/fonts`, SIL OFL) + reportlab QR. company Lambda 전용 문서 레이어(reportlab·pillow·글꼴 /opt/fonts), company는 메모리 512MB·시간 30초 |
| QR | 라벨 QR = 기기 화면 주소. 폰 기본 카메라로 찍으면 바로 열림(앱 안 스캐너 불필요) |
| 정기 청구 | 회사 화면을 열 때 빠진 청구를 만드는 방식(가계부 고정 지출과 같은 원리) — 스케줄러 없음 |
| 회사별 배포 | 회사마다 AWS 계정 + 같은 Terraform. 회사 정보·기능 설정은 설정 화면/초기 데이터로 |
| 추가 비용 | 문서 S3(월 수십 원 수준), Lambda·DynamoDB는 무료 범위 안 예상 |

| A/S | `SERVICE#<id>`, 번호 `AS-YYYY-NNNN`. 접수(거래처·기기·증상·연락처·담당) → 완료(조치·사용 부품·작업비). 부품·작업비가 있으면 A/S 거래(`service`): 부품 재고 감소, 금액이 있으면 미수. 금액 못 보는 기사는 부품만 + "유상" 표시 → `needsBilling` → 사무실이 "청구 만들기"(청구 거래의 `serviceId`). A/S 거래 취소 → 다시 접수 상태·재고 복귀. 접수 취소는 완료 전만 |
| 권한 | 계약 보기·편집 = 계약 영역(출고·수거는 기기 편집도), 청구 대기 = 계약 + 금액 보기, 검침·A/S = 기기 영역, 직원 이름 목록(`/staff`)은 회사 멤버 누구나 |
| 화면 | 메뉴에 임대 계약·청구 대기·검침·A/S. 홈: 오늘 할 일(청구 대기·처리할 A/S·검침 필요) + 빠른 입력(임대 출고·수거·검침·A/S 접수·입금·판매). 기기 상세: 계약·최근 검침, 검침 입력, A/S 접수. 거래처 상세: 계약·처리 중 A/S. 거래 상세: 계약·A/S 연결 |
